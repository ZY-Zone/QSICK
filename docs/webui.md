# WebUI

WebUI 是 QSICK 的操作面板，与内核同进程运行（FastAPI + Jinja2），默认监听
`http://127.0.0.1:5754`。地址、端口与访问令牌都可以在 **设置** 页或 `/network` 页修改。

## 页面

| 页面 | 作用 |
| --- | --- |
| `/` | 仪表盘：两行状态（连接、运行时长、载荷、插件）+ 三块图表（CPU、内存、网络配置）+ 消息数。见下 |
| `/logs` | SSE 实时日志，按级别 / 4 个分类组 / 搜索过滤，暂停、自动滚动、复制、下载、服务端清空 |
| `/actions` | 全部 242 个动作，按内核 / 适配器 / 类别过滤，带结果可复制的 JSON 测试器 |
| `/messages` | 消息库，支持文本/会话搜索、分页、JSON 接口 |
| `/accounts` | 无头实例管理：创建、启动、停止、扫码登录、踢线后自动重登 |
| `/plugins` | 横向插件行：启用开关、配置 / 更新 / 卸载 |
| `/plugins/market` | 远程市场：搜索、排序、点赞、安装/更新（受 `plugins.allow_remote_install` 约束） |
| `/network` | OneBot 地址/端口/令牌、HTTP/WS/SSE 开关与路径、反向 WS 目标、WebUI 监听——即时生效；每条配置都归属一个实例 |
| `/settings` | 管道认证、实时日志级别、消息保留、插件监视 |
| `/config` | 脱敏后的 JSON 视图，可复制 |
| `/metrics` | Prometheus 文本指标（受 WebUI 令牌保护） |
| `/chat` | 聊天栏（需手动启用，见下） |

设置了 `webui.access_token` 时走令牌登录页。页面吸顶导航，布局一路响应到手机宽度。

## 仪表盘上的三块图表

| 图 | 内容 | 数据来源 |
| --- | --- | --- |
| CPU 占用 | 近 30 分钟的**系统**占用折线 + 均值虚线 + 最小二乘拟合曲线 | `GetSystemTimes` 差分，5 秒一次 |
| 内存占用 | QSICK 侧、每个 QQ 主进程（已登录的标 uin）、其他、空闲 | `NtQuerySystemInformation` |
| 网络配置 | 每个**已启用**端点一行，灰/绿灯表示是否有连接；HTTP/WS/SSE 带连接数 | `network_cards()` |
| 消息数 | 近 7 天、每 12 小时一格，按来源账号分段着色 | 消息缓存库的分桶计数 |

几个刻意的取舍：

- **内存用「专用工作集」而不是「工作集」。** QQ 是八个 Chromium 进程，共享的 DLL 页在总工作集里
  每个进程各算一遍，加起来会比任务管理器高出两倍多。`WorkingSetPrivateSize` 才是任务管理器那一列。
- **CPU 是整机占用，不是 QSICK 自己的。** QSICK 的份额小到画不出形状。
- **关闭的端点不显示。** 这一栏回答的是"应该监听的东西现在监听了吗"，一行"未启用"两个问题都没答。
- **HTTP 没有连接数可数。** 它无状态，所以显示的是累计请求数，标签也照实写"次请求"。
- 每块面板超过三行就滚动——三行是"不用滚能看完"的量，不是硬上限。

图表全部是手写 SVG（`app.js` 的 `drawCpu` / `drawMemory` / `drawMessages`），没有图表库：
需要的东西只有折线、堆叠柱和环形图，而坐标系按实际像素设定，所以文字不会被拉伸。

`/static/app.js` 与 `app.css` 的 URL 带 `?v=`，值由文件 mtime 与大小算出（`_asset_version`）。
它原先是手写常量，2026-11-14 之后再没变过——于是之后所有前端改动都被浏览器缓存挡在门外，
"改了没生效"了好几次。

## 登录密码

`webui.access_token` 是给脚本用的共享密钥；密码是给浏览器里的人用的。两条并存，任一通过即可访问。

- 密码只存 scrypt 摘要（含参数），`data/webui/auth.json`，明文不落盘。
- 会话 30 分钟，**有操作即续期**；改密码会让全部会话立即失效。
- 登录记录（时间 + IP + 成功/失败）保留最近 100 条。
- 首次访问且未设密码时，底部出现一条引导横幅，可关掉，7 天内不再问。它不挡界面 ——
  拒绝渲染直到设密码，会把刚装好软件的人锁在外面。

## 显示设置

| 项 | 说明 |
| --- | --- |
| 配色 | 跟随系统 / 浅色 / 深色，存 localStorage，首帧脚本在渲染前应用（不会闪白） |
| 光标 | 系统默认，或导入一套光标包 |

没有"减少动态效果"开关：那是操作系统的无障碍偏好，由 `prefers-reduced-motion` 直接遵循。

### 光标包

一个 ZIP：一份 `cursor.json` 加若干图片。

```json
{
  "name": "我的光标包",
  "description": "不超过十二个字",
  "cursors": { "default": "arrow.png", "pointer": "hand.png" },
  "hotspots": { "default": [1, 1] }
}
```

`name` 与 `description` 必填，`description` 不超过 12 字，两者会显示在设置页的卡片上。
`hotspots` 是点击生效的坐标，省略即 `[0, 0]`。支持 PNG / SVG / WebP / ICO / GIF。

只表达 **4 种状态**：`default`、`pointer`、`text`、`not-allowed`。
`src/qsick/webui/cursor_types.py` 是唯一清单，测试比对它与 `cursor.js` 是否一致。

只留四种是刻意的：光标包要求作者为每个状态画图并标热点，而界面里根本不会出现的状态（`grab`、
`zoom-in`、`col-resize` …）就是白做的工——更糟的是做了却看不到，会让人以为功能坏了。清单只收
那些不需要额外标记就能出现在屏幕上的。要加回一种，在 `cursor.js` 的 `TYPES` 与 `TYPE_SELECTORS`
各加一行、在 `cursor_types.py` 加一条即可。

**包里没定义的状态沿用包的初始箭头，不会退回系统光标** —— 退回系统光标会让系统画一个、包画一个，
也就是两个指针叠在一起。

正因如此，项目**不再提供内置箭头样式**：内置样式要靠一个跟随指针的元素来画，而那个元素无法覆盖
每一个状态，必然出现叠加。光标包走 CSS `cursor`，浏览器原生支持全部状态。

## 缓存清理

设置 → **缓存清理**：左边一块环形图说明"谁占地方"，右边一张表说明"每项多大、怎么清"，外加一个
一键清理。

| 缓存项 | 位置 | 清理动作 |
| --- | --- | --- |
| 各账号原始消息库 | 磁盘 | 逐库清空并 VACUUM |
| 消息缓存库 | 磁盘 | 清空 + VACUUM |
| 日志缓冲区 | 内存 | 丢弃保留的日志行（不动日志文件） |
| WebUI 登录记录 | 磁盘 | 清历史，**不动密码** |
| 媒体文件缓存 | 磁盘 | 删除目录下全部文件 |

几条刻意的取舍：

- **配置、插件、登录密码不列为缓存。** 一个能删掉密码的「一键清理」是个陷阱。
- **尺寸按文件系统量，不按行数估。** SQLite 的 `-wal` 常常比库本身还大（实测 13MB 对 106MB），
  只报 `.db` 会把缓存量说小一大截。
- **释放量是「清理前减清理后」，不是清理代码的承诺。** DELETE 不配 VACUUM 时页面照样
  占着空间，承诺和磁盘会不一致；差值不会。
- 单项失败不打断「一键清理」：一项清不掉，其余的照清。

## 认证

- 除登录页外，所有页面与接口都要求 WebUI 令牌（`webui.access_token`）。
- `/metrics` 也在令牌之后——它含消息量与动作统计，不适合匿名暴露。
- 令牌用 `secrets.compare_digest` 比对，不做前缀匹配。

## 聊天栏（需手动启用）

导航里的 **聊天** 一项在 `webui.chat_enabled` 为 false 时带一个 `待启用` 徽标，打开会显示
红色警告弹窗：

> 如果这是在公网服务器上运行的程序，可能会导致您的 QQ 号处于危险中。

确认按钮初始为 `确认启用 (3)`，三秒内灰置不可点，然后变蓝。启用会把
`webui.chat_enabled=true` 写进配置；之后聊天页提供群列表、消息流与发送框，并带一个
**停用聊天** 按钮。停用期间 `/api/chat/send` 会被拒绝。

### 实例切换

聊天栏右上角可以切换实例。切换后会话列表、历史、发送都落在该实例上：

- **读**：历史只从它自己的库读（`data/instances/<实例>/messages.db`）；
- **发**：动作带上该实例的账号，用它的号发出，不会落到主实例。

### 增量轮询

聊天栏每 3 秒轮询一次，但走的是增量接口（`/api/chat/history?after=<最新 id>`），
只问"比已知最新一条更新的消息"。没有新消息时后端只读一小段、前端连重渲染都不触发：

| 方式 | 耗时 | 返回 |
| --- | --- | --- |
| 全量 `limit=80` | 11.46 ms/次 | 80 条 |
| 增量 `after=` | 1.31 ms/次 | 通常 0 条 |

历史列表的查询也已下推到 SQL（`page()` 走 `(chat_type, chat_id, time)` 索引，
`conversation_summaries()` 用窗口函数取每组最新一行），不再把整个库读进内存。

## 相关接口

页面之外，WebUI 还暴露一组供前端与脚本使用的 JSON 接口：

| 端点 | 用途 |
| --- | --- |
| `/api/network/profiles` | 网络配置的增删改与即时应用 |
| `/api/accounts` | 实例列表、创建、启动/停止、退出登录 |
| `/api/chat/*` | 会话、历史、发送、媒体、表情、收藏、撤回、删除 |
| `/api/headless/event` | 宿主上报事件（回环地址 + 每实例随机令牌） |
| `/api/plugins/*` | 插件列表、配置读写、安装/卸载 |
| `/api/logs` | 日志快照与 SSE 流 |
